01
Category 01 / 04

Layout & Hierarchy

How KPIs, charts, and tables are arranged and ordered — and whether that arrangement repeats predictably from tab to tab.

01 · Layout & Hierarchy

What's working

Works well
Summary before detail, every time
Within any single tab, big numbers lead and supporting charts/tables follow. That ordering never breaks — it's the one rule every tab agrees on.
Components share one design system
Individual tiles, charts, and cards are visually consistent wherever they appear — the problem is never the pieces, only how each tab composes them (next slide).
Good instinct on Overview
Pairing big-number KPI tiles with a compact reference fact-list (Founded / HQ / Net Zero) instead of forcing unrelated data into the same tile shape.
01 · Layout & Hierarchy

What needs work

Needs improvement
No shared layout template
Nine tabs, at least eight different arrangements for the same kind of content — flat KPI rows, hero-tile grids, plain tables with no charts at all, one tab with no tiles whatsoever.
Four different filter patterns
No filter, one dropdown, two dropdowns, and a removable chip — all on the same dashboard, for the same kind of interaction.
Reads as built tab-by-tab
Not "designed for what each tab communicates" — more like each was built independently, without a shared widget template to draw from.
02
Category 02 / 04

Accessibility

WCAG 2.1 AA — color contrast, touch targets, and whether chart data actually reaches a screen reader.

02 · Accessibility

What's working

Works well — measured, not estimated
Contrast clears AA everywhere sampled
Resolved the dashboard's oklch() colors to sRGB and measured against their backgrounds directly — every value is well above the 4.5:1 AA minimum.
Tab targets are comfortably sized
Header tabs render at 34px tall — well above the 24×24px WCAG 2.2 AA minimum for touch/click targets.
The right mechanism is in place
Every chart already carries role="img" and an aria-label — the plumbing exists, it's just not filled in well (next slide).
Measured contrast — Overview tab
KPI value ("119")15.42 : 1
KPI label ("Farms")9.57 : 1
Chart title15.42 : 1
Axis tick15.42 : 1
Secondary label9.57 : 1
AA requires 4.5:1 for normal text. The lowest value measured here — 9.57:1 — already clears the 7:1 AAA bar.
02 · Accessibility

What needs work

Needs improvement
Chart labels name the shape, not the data
Every chart's aria-label just says "Bar chart" or "Line chart" — a screen reader user never hears what the chart actually shows, or its values.
No data fallback anywhere
No <title>/<desc> with real content, no hidden data table alongside any chart — the insight in every chart, on every tab, is currently unavailable non-visually.
Keyboard-only nav — still open
Not yet verified end to end for widget "···" menus and filter dropdowns. Flagged as a follow-up, not claimed as tested.
03
Category 03 / 04

Aesthetic

Visual consistency across tabs — theme, component styling, and whether the same kind of element looks the same everywhere.

03 · Aesthetic

What's working

Works well
Dark theme holds across all nine tabs
Background, card, and text colors read identically everywhere — no light-mode leakage, no inconsistent surfaces anywhere in the dashboard.
Components themselves are consistent
Individual tile and chart styling comes from the same design system wherever it appears — the inconsistency lives one level up, in how tabs compose them.
03 · Aesthetic

What needs work

Needs improvement
A dev/demo widget is live in production
"Markdown Notation Guide" — test documentation for whoever built the widget, still sitting on the Climate & Carbon tab. Nothing a stakeholder should ever see.
Two tables, two different styles
Same dashboard, same tab: one table with full grid-line borders, the neighboring one with a shaded header and no borders at all.
"Show more" only on some tables
One table says "Showing 8 of 360 rows — open tracker." The two right beside it say nothing at all.

Category 04 / 04

Font Implementation

Typeface choice, type-scale discipline, and whether numbers are formatted for what they actually represent.

04 · Font Implementation

What's working

Works well
Type scale holds, where roles exist
KPI values, chart titles, and axis labels each keep the same size/weight pairing everywhere they're used — that discipline doesn't break.
Numeric columns align cleanly
The plain-table tabs (Key Metrics, Farm Profile, Data Tables) right-align every numeric column correctly — no misalignment found there.
Type scale — sampled roles
KPI value24px / 600
Chart / card title18px / 600
Label / axis text11–13px / 400
Font stack: system UI (ui-sans-serif, system-ui, …) — fast and native, but no distinct typographic identity for Samara yet. Worth a deliberate call either way.
04 · Font Implementation

What needs work

Needs improvement
Years are getting thousands separators
Farm Profile renders 1,985 and 2,019 as "Oldest / Newest Established." These are years, not quantities — a real formatting bug, not a display choice.
No canonical label for the same metric
One emissions figure shows up as Total CO₂ (t), Total Emissions, and Total Emissions (t CO₂) — depending only on which tab you're looking at.
Across all four categories

Every category points at the same root cause: this dashboard was built tab-by-tab, not designed as one system.

01Eight layout arrangements and four filter patterns for one repeated kind of content.
02The right accessibility plumbing exists — it was just never filled in with real content.
03A leftover developer widget shipped straight into a stakeholder-facing dashboard.
04The same number gets a different label and a different format depending on which tab renders it.
Where this goes next

Next steps

01Remove the "Markdown Notation Guide" widget from Climate & Carbon.
02Fix the comma-formatted-year bug on Farm Profile, and audit for the same pattern elsewhere.
03Give every chart a real aria-label — or a hidden data table — instead of a chart-type-only label.
04Define one shared KPI/chart layout template so tabs stop each inventing their own arrangement.
05Standardize the "show more rows" affordance across every table, not just some.
